## 1. 논리적 직렬화

프론트엔드서 진행하는 직렬화와 백엔드서 진행하는 직렬화가 **같아야**, 인라인 댓글의 offset을 정확하게 일치시킬 수 있습니다.

이때, 백엔드에서 받는 Content 형식은 Json이며, 하나의 블록 안에 여러 Text가 존재하는 BlockNote구조입니다. 따라서 Client로부터 받는 Content를 그대로 사용하면, 화면상 한 블록에 직렬화되어있는 문자열을 얻을 수 없습니다. 따라서 이를 직렬화해야합니다.

의를 의사코드로 보여주면 다음과 같다.
```text
// UI로 보여질 때,
안녕하세요. 송송입니다.

// Client에게 받을 때,
blockId = 1
1. 안녕하세요
2. 송송 (blod체)
3. 입니다.
```
다음과 같은 1,2,3을 백엔드는 한줄로 직렬화하여 `안녕하세요 송송입니다.`를 완성한 후, 인라인댓글 처리를 시작해야합니다.

공통 원칙은 다음과 같습니다.
- `content` 배열의 순서를 유지.
- 문자, 공백, 탭, 개행을 원문 그대로 보존.
- 임의의 공백이나 구분자를 추가하지 안함.
- `trim`, 공백 병합, Unicode 정규화를 하지 안함.
- offset은 UTF-16 code unit을 기준으로 계산.
- 범위는 `[startOffset, endOffset)` 형식을 사용.

## 2. 직렬화 규칙 정하기

blockId안에 type이 존재하며, 이 type을 어떻게 다루면서 직렬화할 지 정해야합니다.
### 2-1. Text Block은 어떻게 할 것인가
#### 2-1-1. 그대로 사용.
`type`이 `text`인 inline content는 `text` 필드의 값을 **그대로** 사용한다.
결국 띄어쓰기, 공백이 있어도, 사용자의 의도이므로, 그대로 처리해야합니다.
##### 입력
```
[
  {
    "type": "text",
    "text": "타입스크립트는",
    "styles": {}
  }
]
```
##### 직렬화 결과
```
타입스크립트는
```
#### 2-1-2. 공백 제거 X
문자열 앞뒤에 공백이 있어도 제거하지 않습니다.
##### 입력
```
[
  {
    "type": "text",
    "text": " 값이 있습니다. ",
    "styles": {}
  }
]
```
##### 직렬화 결과
```
 값이 있습니다. 
```
빈 문자열은 그대로 빈 문자열로 처리합니다.
```
{
  "type": "text",
  "text": "",
  "styles": {}
}
```

```
""
```

---
### 2-2. Link Block은 어떻게 할 것인가
규칙에 따라 어떻게 직렬화 되는 지 [예시]
BlockNote에서 링크는 독립적인 블록이 아니라 `type: "link"`인 inline content입니다.
#### 2-2-1. 내부 Text만 포함하고 링크값은 직렬화 포함 X
링크는 `href`를 직렬화 결과에 포함하지 않고, `content` 배열 내부의 `text`만 순서대로 연결합니다.
##### 입력
```
[
  {
    "type": "text",
    "text": "자세한 내용은 ",
    "styles": {}
  },
  {
    "type": "link",
    "href": "https://example.com",
    "content": [
      {
        "type": "text",
        "text": "공식 문서",
        "styles": {}
      }
    ]
  },
  {
    "type": "text",
    "text": "를 참고하세요.",
    "styles": {}
  }
]
```
##### 직렬화 결과
```
// 공식 문서는 UI상 하이퍼링크 처리됨. 그러나 백엔드는 단순 text 직렬만 필요.
자세한 내용은 공식 문서를 참고하세요.
```

#### 2-2-2. 링크 내부 여러 `text`는 모두 이어서 처리.
링크 내부에 여러 개의 `text`가 있다면 모두 순서대로 연결합니다.
##### 입력
```
{
  "type": "link",
  "href": "https://example.com",
  "content": [
    {
      "type": "text",
      "text": "공식 ",
      "styles": {}
    },
    {
      "type": "text",
      "text": "문서",
      "styles": {
        "bold": true
      }
    }
  ]
}
```
##### 직렬화 결과
```
공식 문서
```

링크 주소가 변경되더라도 표시되는 텍스트가 같다면 직렬화 결과와 offset은 변경되지 않습니다.

---
### 2-3. styles는 어떻게 할 것인가
#### 2-3-1. 스타일은 직렬화 결과 무관.
`bold`, `italic`, `code` 등의 스타일은 직렬화 결과에 포함하지 않는다.
##### 입력
```
[
  {
    "type": "text",
    "text": "타입 검사를 ",
    "styles": {}
  },
  {
    "type": "text",
    "text": "통과했습니다",
    "styles": {
      "bold": true
    }
  },
  {
    "type": "text",
    "text": ".",
    "styles": {}
  }
]
```
##### 직렬화 결과
```
타입 검사를 통과했습니다.
```

---
### 2-4. inline 경계는 어떻게 할 것인가?
`content` 배열에 여러 inline content가 있으면 배열 순서대로 텍스트를 연결해야합니다.

#### 2-4-1. 공백 구분자를 임의로 추가하지 않는다.
inline content 사이에는 공백이나 구분자를 **임의로 추가하지 않습니다**. 필요한 공백은 각 `text` 값에 이미 포함되어 있기 때문입니다.
##### 입력
```
[
  {
    "type": "text",
    "text": "처음에는 ",
    "styles": {}
  },
  {
    "type": "text",
    "text": "Discount | undefined",
    "styles": {
      "code": true
    }
  },
  {
    "type": "text",
    "text": "였던 타입이 ",
    "styles": {}
  },
  {
    "type": "text",
    "text": "Discount",
    "styles": {
      "code": true
    }
  },
  {
    "type": "text",
    "text": "로 좁혀집니다.",
    "styles": {}
  }
]
```
##### 직렬화 결과
```
처음에는 Discount | undefined였던 타입이 Discount로 좁혀집니다.
```
inline 경계에 공백을 추가하면 안 됩니다.

---
### 2-5. \n(개행)은 어떻게 할 것인가

#### 2-5-1. 개행은 그대로 보존한다.
`text` 값에 포함된 `\n`은 제거하거나 공백으로 치환하지 않고 그대로 보존합니다.
BlockNote에서 사용자가 입력한 강제 개행과 코드 블록의 줄바꿈이 `text` 내부의 `\n`으로 전달되기 때문입니다.
##### 입력
```
[
  {
    "type": "text",
    "text": "첫 번째 문장입니다.\n두 번째 문장입니다.",
    "styles": {}
  }
]
```
##### 직렬화 결과
```
첫 번째 문장입니다.
두 번째 문장입니다.
```
문자열 표현으로 나타내면 다음과 같습니다.
```
"첫 번째 문장입니다.\n두 번째 문장입니다."
```
#### 2-5-2. trim() 호출 X
`trim()`을 호출하지 않기 때문에 문자열 마지막의 개행도 보존합니다.
##### 입력
```
[
  {
    "type": "text",
    "text": "문장이 끝납니다.\n",
    "styles": {}
  }
]
```
##### 직렬화 결과
```
"문장이 끝납니다.\n"
```

#### 2-5-3. 빈 content와 개행을 구분.
`content: []`인 빈 블록과 `text: "\n"`인 블록도 구분합니다.
##### 빈 content
```
{
  "content": []
}
```
##### 직렬화 결과:
```
""
```
##### 문자열 길이:
```
0
```
##### 개행만 존재하는 content
```
{
  "content": [
    {
      "type": "text",
      "text": "\n",
      "styles": {}
    }
  ]
}
```
##### 직렬화 결과:
```
"\n"
```
##### 문자열 길이:
```
1
```

> JavaScript와 Java 모두 해당 `\n`을 하나의 **UTF-16 code unit**으로 계산해야 합니다.

## 3. 직렬화 규칙 한줄 정리.
- text        → text 값을 그대로 추가 
- link        → link.content 내부 text를 순서대로 추가 
- styles      → 무시 
- inline 경계 → 별도 구분자 없이 연결 
- \n          → 그대로 보존
