# 게시글 상세 코로그 통계 제거

## 목표와 범위

- 이슈: https://github.com/woowacourse-teams/2026-rilog/issues/836
- 코로그 게시글의 일반·수정용 상세 조회에서 멤버 수와 공개 발행 글 수 집계를 제거한다.
- `owner.memberCount`, `owner.postCount`를 응답에서 제거한다.
- 프론트엔드, 코로그 홈 통계, 권한 정책, 조회수 및 DB 스키마는 변경하지 않는다.

## 구현 계획

1. 기존 상세 조회 테스트로 권한과 응답 동작을 확인한다.
2. 집계 호출이 없는 일반·수정용 상세 조회와 집계 필드가 없는 직렬화 응답을 테스트로 명세하고 실패를 확인한다.
3. `PostService`의 집계 호출·전용 메서드, DTO 필드·인자와 사용처가 사라진 repository 메서드를 삭제한다.
4. 기존 집계 테스트를 새 응답 계약 검증으로 바꾸고 Swagger 예시를 갱신한다.
5. 관련 테스트, 전체 백엔드 테스트 및 빌드를 실행하고 별도 리뷰를 받는다.

## 유지할 동작

- 코로그의 나머지 프로필 필드와 게시글 정보는 그대로 반환한다.
- 개인 블로그 상세 응답, 읽기·수정·삭제 권한 및 조회수 반환 정책은 유지한다.
- 멤버 권한 확인에 필요한 `BlogMemberRepository`와 다른 기능에서 사용하는
  `countActiveMembersByBlogId`는 유지한다.

## API 호환성과 배포 순서

이번 변경은 코로그 상세 응답의 필수 필드 두 개를 제거하는 계약 변경이다.
현재 프론트엔드 응답 검증은 두 필드를 필수 숫자로 요구하므로 백엔드만 먼저 배포하면
코로그 상세 조회가 실패한다. 프론트엔드 검증 완화를 별도 작업으로 연결하고 먼저 배포하거나
동시에 반영해야 한다. 이 작업에서는 프론트엔드 파일을 수정하지 않는다.

## 검증

- Java 21에서 관련 서비스·통합·컨트롤러 테스트 65개가 통과했다.
- 구현 전 집계 호출과 JSON 필드에 대한 회귀 테스트 4개가 예상대로 실패하고 구현 후 통과했다.
- `./gradlew test check build`: 전체 테스트 1,483개 통과, check·빌드 성공.
- 별도 리뷰에서 수정이 필요한 문제는 발견되지 않았다.
- 프론트엔드 변경과 삭제한 집계 메서드의 잔여 호출이 없음을 확인했다.
- CI와 같은 `./gradlew testMySql`: MySQL 8.4.6에서 전체 테스트 1,483개 통과.
