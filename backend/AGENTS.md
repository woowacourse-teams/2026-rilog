# Rilog 백엔드 작업 규칙

루트 `AGENTS.md`와 파트의 기존 기술 문서를 함께 따른다. 백엔드 스택과 검증 방식은 백엔드 팀이 결정하며, 이 하네스는 이를 임의로 정하지 않는다.

## 결정 원칙

- 현재 backend 소스와 build 설정을 우선한다.
- 기술 스택, 계층 구조, 데이터베이스, migration과 검증 도구는 백엔드 팀의 합의 없이 추가하지 않는다.
- 백엔드 팀이 결정을 확정하면 실제 설정과 이 문서를 함께 갱신한다.

## 공통 경계

- frontend에 영향을 주는 API 변경은 영향과 호환성 계획을 PR에 기록한다.
- secret, 실제 credential과 production 데이터는 저장소나 테스트 fixture에 넣지 않는다.

## 검증

- 현재 backend build 설정에 실제로 정의된 검증을 실행한다.
- 추가 검증 방식과 CI 연결은 백엔드 팀이 확정한 뒤 문서화한다.

## Code Review Rules

- 호환성 계획 없는 breaking API 변경을 지적한다.
- 백엔드 팀이 합의하지 않은 스택이나 구조를 임의로 도입한 변경을 지적한다.
