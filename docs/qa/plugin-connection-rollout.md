# 이관 사이트 관리자 자동 연결 배포

## 적용 순서

1. 로컬에서 연결 화면, 사용자 승인, 1분 이상 경과한 토큰 갱신, 중지·계정 변경을 검증한다. 실제 개발 API 검증과 모의 API 브라우저 검증은 결과에 구분해 기록한다.
2. Rilog 프론트 변경을 `develop` 대상 PR로 검토한다. 이번 변경은 `/plugin-connect`와 그 인증·메시지 처리 및 테스트에 한정하며, 백엔드나 기존 글쓰기 기능은 변경하지 않는다.
3. 검증한 변경을 기존 릴리스 절차로 `production`에 반영하고 운영 프론트 workflow 성공과 실제 `https://www.rilog.kr/plugin-connect` 응답을 각각 확인한다. 운영 배포는 별도 요청과 팀 절차를 따른다.
4. 이관 사이트를 자동 연결 지원 코드로 배포하되 `RILOG_FRONTEND_BRIDGE_ENABLED`는 기본 비활성으로 둔다. 연결 화면이 실제 배포되기 전에는 수동 ACCESS 토큰 연결을 계속 제공한다.
5. 배포된 Rilog 연결 화면의 실제 popup/opener와 정확한 Site origin·state·환경 검증을 확인한 뒤 위 변수를 `true`로 설정해 자동 연결을 활성화한다. 두 창을 열어두고 최초 토큰 만료 후에도 연결이 갱신되는지 확인한다.

프론트 PR은 `develop`을 대상으로 검토하고, 운영 반영은 기존 릴리스 절차로 진행한다. `develop`·`production` 직접 푸시로 우회하지 않는다.

## 환경 구분

| 항목 | 개발 | 운영 |
| --- | --- | --- |
| API | `https://develop.rilog.kr` | `https://api.rilog.kr` |
| 최초 로그인 | 개발 API에 연결된 로컬 Rilog 프론트 | 운영 Rilog 프론트 |
| 로컬 프론트 | `http://localhost:3000` | 해당 없음 |
| 배포 프론트 | 별도 개발 배포 없음 | `https://www.rilog.kr` |
| 자동 연결 | 같은 개발 프론트 또는 기존 개발 로그인 쿠키가 있는 운영 프론트에서 검증 | 운영 프론트에서 로그인·갱신 |

운영 빌드의 GitHub callback은 운영 API를 사용한다. 따라서 운영 연결 화면이 개발 토큰을 갱신할 수 있어도 새 개발 로그인을 수행할 수 있다는 뜻은 아니다. 개발 로그인이 없으면 개발 API에 연결된 로컬 프론트에서 먼저 로그인한다. 개발·운영 ADMIN 권한은 각각 확인한다.

Site의 `RILOG_API_BASE_URL`은 그대로 유지한다. 운영 프론트 연결 화면을 배포했다는 이유만으로 Site의 발행 API를 운영으로 전환하지 않는다. API origin을 바꾸면 사용자마다 다시 연결해야 한다.

## 확인 항목과 복구

- 사용자 승인 전 ACCESS 토큰이 Site로 전달되지 않는다. 토큰은 URL·브라우저 저장소·로그·스크린샷·모델 컨텍스트에 포함되지 않는다.
- 잘못된 origin·popup·state·환경의 메시지는 거절한다. USER 계정은 연결하지 않고 계정 교체·중지·창 종료 시 갱신을 멈춘다.
- 최초 토큰 만료 후 새 ACCESS 토큰이 저장되고, 이미지 업로드 직전과 발행 직전에 동일 관리자의 최신 토큰을 사용한다.
- GitHub 로그인은 별도 창에서 완료하고 기존 연결 창에서 다시 연결한다. 브라우저의 팝업·쿠키·백그라운드 타이머 정책으로 중단되면 수동 연결을 안내한다.
- 실패 시 먼저 Site의 자동 연결 변수를 비활성화해 수동 연결로 복구한다. Rilog 배포 되돌리기는 기존 릴리스 절차를 따르며 사용자 토큰이나 DB를 직접 수정하지 않는다.
- 실제 게시글·S3 쓰기 검증은 지정된 테스트 작성자·원문으로 별도로 수행한다. 인증 검증만으로 발행 성공을 주장하지 않는다.

## 2026-10-28 준비 검증 결과

- Rilog 프론트 `pnpm check`와 popup E2E를 통과했다. E2E는 모의 API·62초 가상시간으로 갱신과 중지를 확인한다.
- Site 라이브러리 테스트 75개, 타입·린트 통과. 모의 브라우저에서 기본 비활성, 출처 검증, 반복 갱신, 계정 변경 차단을 확인했다.
- 실제 개발 API에서 localhost:3000 Rilog와 localhost:4317 Site를 연결해 ADMIN 인증과 로컬 암호화 저장을 확인했다. 최초 토큰의 만료 시점을 넘긴 후 새 만료 시각으로 연결이 유지됐고, 갱신된 인증으로 발행 블로그 조회가 HTTP 200을 반환했다. 기존 개발 로그인 쿠키를 사용했으며 새 GitHub 로그인 경로는 실행하지 않았다.
- 실제 글 발행과 S3 업로드는 수행하지 않았다. 검증용 Site 연결·로컬 키·임시 서버는 검증 후 정리한다.
- 확인 당시 운영 `/plugin-connect`는 HTTP 404였다. 이 문서의 검증 결과는 운영 배포와 Site 자동 활성화 완료를 의미하지 않는다.
