# 게시글 읽기 계측 v2

관련 이슈: [#690](https://github.com/woowacourse-teams/2026-rilog/issues/690). 결정 기록: [ADR 0006](../adr/0006-post-reading-metric.md).

## 정의와 이벤트

`post read qualified`는 한 글 방문에서 본문 깊이 50% 이상에 한 번 도달하고, 문서가 보이는 동안 누적 체류시간이 20초 이상이면 한 번 발생한다. 충족 순서는 무관하다. 숨김 시간은 제외하고 복귀하면 이어 센다. 마우스·키보드 활동 조건은 없다.

| 속성                    | 값                                                    |
| ----------------------- | ----------------------------------------------------- |
| `post_id`               | 글 ID (number)                                        |
| `engagement_seconds`    | 전송 시 실제 누적 가시 체류 밀리초 / 1000 (소수 허용) |
| `scroll_depth_bucket`   | `50_percent`                                          |
| `read_tracking_version` | `2`                                                   |

기존 `post read engaged`는 최초 깊이 도달 때의 정수 체류시간을 기록하는 이벤트로 유지한다. 예를 들어 5초에 50% 도달하고 계속 읽으면 기존 이벤트는 5초, 새 이벤트는 누적 20초에 발생한다. 타이머 지연 또는 깊이 도달이 늦으면 실제 체류시간은 20초보다 클 수 있다.

깊이는 기존 `(viewport height - article top) / article height`를 0~1로 제한하는 계산을 유지한다. 짧은 글은 최초 표시부터 깊이를 만족할 수 있으나 20초 전에는 새 이벤트가 없다. 숨겨진 문서는 깊이 평가와 두 읽기 이벤트 전송을 하지 않고, 다시 보일 때 재평가한다.

## 방문 경계와 구현

같은 본문 컴포넌트가 유지되는 동안은 같은 방문이다. 같은 글의 재렌더링, props 변경, 반복 스크롤·리사이즈와 StrictMode effect 재실행은 새 방문이 아니다. 신규 읽기의 깊이 이력과 전송 여부는 post ID별 컴포넌트 ref로 보존한다. post ID가 바뀌거나 실제 언마운트 후 새 컴포넌트가 마운트되면 새 방문이다. 같은 task 안의 A→B→A 전환에서도 이전 깊이를 재사용하지 않는다. 기존 조회·50% 이벤트는 종전 tracker의 0ms 정리 방식을 유지한다.

다른 글은 별도 방문 상태와 시간 reset key를 사용한다. 앱의 BasePostDetail은 post ID로 subtree를 key 처리하므로 SPA 글 이동에서 이전 글이 해제된다. 다른 경로로 떠난 뒤 뒤로가기로 다시 마운트하면 새 방문이며 다시 20초와 깊이를 충족해야 한다. A를 10초 읽다가 다른 페이지로 떠난 뒤 A로 돌아오면 이전 10초를 이어 세지 않고 0초부터 다시 시작한다. hash/query만 바뀌고 같은 본문이 유지되는 경우는 새 방문으로 세지 않는다. 전체 문서 새로고침은 메모리 상태가 초기화되어 새 방문이다.

기존 `useActiveElapsedTime`의 시간/visibility 계산에 남은 가시시간을 위한 timeout 하나를 연결한다. 주기 polling이나 별도 체류 interval은 없다. visibilitychange, scroll, resize와 timeout은 해제 시 정리한다. 기존 탐색의 navigation_visit_id는 다른 이벤트의 조합용이므로 읽기 이벤트에 새 방문 식별자나 개인정보를 추가하지 않는다. 사용자 식별은 기존 PostHog distinct ID/identify/reset과 capture 경계를 그대로 사용한다.

## 대시보드 연결 후속

- 일일 독자 수: `post read qualified` + `read_tracking_version = 2`로 제한하고 날짜별 고유 사용자 수를 센다. 일 경계는 Asia/Seoul로 명시한다.
- 읽은 글 수: 같은 날짜/기간에서 사용자와 `post_id` 조합을 중복 제거한다. 방문 이벤트 수는 재방문을 포함하므로 조합 수와 다르다.
- 로그인/익명은 기존 식별 병합 정책을 따른다. 코드에서 팀·테스트 사용자 제외를 새로 정의하지 않는다. 연결할 대시보드의 기존 cohort/person 필터를 유지해야 한다. 이 작업에서는 운영 cohort 설정을 조회하거나 변경하지 않았다.
- 기존 50% 이벤트와 신규 v2 이벤트를 합산하지 않는다. 과거 이벤트의 20초 필터로 v2 과거 데이터를 복원할 수 없다.
- 운영 적용 시점은 아직 미정이다. 이슈 생성일이나 로컬 테스트 시간을 적용 시점으로 사용하지 않는다. 실제 production 배포 SHA, 적용 완료 시각(KST 및 UTC), 최초 운영 수집 timestamp를 배포 담당자가 기록한 뒤 그 시점 이후를 집계한다.

## 운영 수집 확인 (배포 후 별도 수행)

배포 SHA/시각과 최초 수집 시각을 기록하고, 실제 글에서 5초 깊이 도달 후 추가 스크롤 없이 20초에 새 이벤트 한 건, 탭 숨김 60초 제외, 재방문 초기화를 확인한다. payload의 post_id/실제 체류시간/version을 확인하고 기존 팀·테스트 사용자 필터 적용 전후 결과를 비교한다. SDK 호출/로컬 테스트 성공은 서버 수집 성공의 증거가 아니다. 대시보드 변경·병합·운영 배포는 별도 작업에서 수행한다.
