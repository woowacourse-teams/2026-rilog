# 게시글 읽기 계측 v2

관련 이슈: [#690](https://github.com/woowacourse-teams/2026-rilog/issues/690). 결정 기록: [ADR 0006](../adr/0006-post-reading-metric.md).

## 수집 계약

`post reading progress`는 글 방문의 누적 상태를 여러 번 기록한다. 문서가 보이는 동안 누적 가시 체류시간 10초 간격으로, 최초 본문 50% 도달 시, 문서 숨김 시 현재 상태를 전송한다. 글 이동·실제 언마운트·`pagehide`에서도 마지막 상태 전송을 시도한다. 같은 누적 시간과 깊이 상태는 중복 전송하지 않는다. 10초는 **전송 간격**이며 읽기 판정 기준이 아니다. 20초 미만 방문도 상태를 수집할 수 있다.

| 속성                     | 값                                                    |
| ------------------------ | ----------------------------------------------------- |
| `post_id`                | 글 ID (number)                                        |
| `reading_visit_id`       | 글 방문마다 새로 만든 비개인 식별자 (string)          |
| `engagement_seconds`     | 전송 시 실제 누적 가시 체류 밀리초 / 1000 (소수 허용) |
| `has_reached_50_percent` | 본문 50%에 한 번 이상 도달했는지 (boolean)            |
| `read_tracking_version`  | `2`                                                   |

기존 `post read engaged`는 최초 50% 도달 때 정수 체류시간과 `scroll_depth_bucket: 50_percent`를 기록하는 이벤트로 유지한다. 예를 들어 5초에 50%에 도달하고 30초까지 머물면 기존 이벤트에는 5초가 기록된다. 새 이벤트는 5초에 도달 상태를 기록한 후 10초·20초·30초 등에서 누적 시간을 갱신한다. 50%에 도달하지 않은 긴 방문은 `has_reached_50_percent: false`인 상태를 남긴다.

깊이는 기존 `(viewport height - article top) / article height`를 0~1로 제한하는 계산을 유지한다. 짧은 글은 최초 표시부터 50%를 만족할 수 있다. 문서가 숨겨진 동안 깊이를 새로 충족시키지 않으며, 복귀 후 다시 평가한다. 한 번 도달했다면 이후 위로 스크롤해도 true로 유지한다. 숨김 시간은 체류시간에서 제외하고 복귀 후 같은 방문에서 이어 센다. 마우스·키보드 활동 조건은 없다.

## 방문 경계와 전송 한계

같은 본문 컴포넌트가 유지되는 동안은 같은 글 방문이다. 같은 글의 재렌더링, props 변경, 반복 스크롤·리사이즈와 StrictMode effect 재실행은 방문 ID를 바꾸지 않는다. 다른 글이나 다른 페이지로 이동한 뒤 다시 방문하면 새 ID, 0초, 깊이 false로 시작한다. `pagehide` 후 `pageshow`로 기존 문서가 복귀하는 경우도 새 방문으로 시작한다. 전체 문서 새로고침도 새 방문이다. hash/query만 바뀌고 같은 본문이 유지되면 새 방문으로 세지 않는다. 기존 `navigation_visit_id`는 글 ID로 key 처리된 탐색 Provider에서 필요할 때 생성되므로 일반적인 글 이동·재방문은 구분하지만, `pagehide`·`pageshow` 후 Provider가 유지되면 그대로 남는다. 읽기 방문의 초기화 경계와 달라 재사용하지 않는다. 세션 ID도 글 방문보다 범위가 넓다.

기존 `useActiveElapsedTime`의 누적·가시성 계산을 사용한다. 제품의 분석 경계는 PostHog JS SDK의 `capture`를 호출하며 별도의 성공 확인 응답을 받지 않는다. 문서 숨김과 `pagehide`에서는 SDK에 `transport: 'sendBeacon'`을 요청한다. 브라우저·SDK가 비콘 전송을 사용하더라도 마지막 호출은 최선의 전송 시도일 뿐 서버 수집을 보장하지 않는다. 주기 전송은 마지막 상태가 누락되어도 일부 누적 시간을 남기기 위한 장치다. 10초 미만 방문은 마지막 전송이 누락되면 방문 전체가 관측되지 않을 수 있고, 관측된 최댓값은 실제 체류보다 전송 간격 또는 마지막 전송 누락만큼 작을 수 있다. 타이머 지연과 네트워크·차단 설정도 수집량에 영향을 준다.

## 대시보드 연결 후속

1. `post reading progress`와 `read_tracking_version = 2`만 대상으로 `reading_visit_id`별 이벤트를 묶는다.
2. 방문의 누적 시간은 `engagement_seconds`의 **최댓값**으로, 깊이 도달은 `has_reached_50_percent`가 방문 중 한 번이라도 true였는지로 구한다.
3. 기본 읽기 기준은 **50% 도달 AND 누적 가시 체류시간 20초 이상**으로 둔다. 동일한 수집 데이터에서 10초·30초 기준도 계산해 비교한다.
4. 일일 독자 수는 기준을 충족한 방문의 날짜별 **고유 사용자 수**, 읽은 글 수는 같은 날짜·기간의 **사용자·`post_id` 조합 수**로 센다. 날짜 경계는 Asia/Seoul로 명시한다.

이벤트 수는 전송된 상태 표본 수이며 읽기 방문 수와 다르다. 한 방문은 여러 이벤트를 만들 수 있고, 한 사용자는 여러 방문·글을 읽을 수 있다. 로그인/익명은 기존 식별 병합 정책을 따르고, 연결할 대시보드의 팀·테스트 사용자 cohort/person 필터를 확인한다. 이 작업은 운영 cohort 설정을 변경하지 않는다. 기존 `post read engaged`나 과거 50% 기준 데이터는 새 지표와 합산하지 않는다. 기존 이벤트에 시간 필터를 적용해 v2 과거 데이터를 복원할 수도 없다.

운영 적용 시점은 미정이다. 이슈 생성일이나 로컬 테스트 시간을 적용 시점으로 사용하지 않는다. production 배포 SHA, 적용 완료 시각(KST 및 UTC), 최초 운영 수집 timestamp를 기록하고 이후 기간부터 집계한다. 이벤트 도착일과 실제 방문일의 경계, 마지막 전송 누락으로 기준 바로 아래에 관측될 수 있는 방문은 대시보드 해석에 반영한다.

## 운영 수집 확인 (배포 후 별도 수행)

실제 글에서 5초에 50% 도달 후 30초까지 체류하며 같은 `reading_visit_id`에 누적 시간이 갱신되는지 확인한다. 50% 미도달 장기 체류의 false 상태, 탭 숨김 60초 제외와 복귀 후 ID 유지, 글 이동·재방문의 ID·시간·깊이 초기화, 종료 직전 이벤트 누락 가능성을 점검한다. payload 필드와 기존 `post read engaged`의 최초 도달 계약을 비교한다. 운영에서 팀·테스트 사용자 필터 적용 전후 결과를 확인한다. SDK 호출이나 로컬 테스트 성공은 서버 수집 성공의 증거가 아니다. 대시보드 변경·병합·운영 배포는 별도 작업에서 수행한다.
