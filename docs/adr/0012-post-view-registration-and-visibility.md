# ADR 0012: 조회 등록과 상세 삭제 권한 기반 조회수 공개

- 상태: 승인
- 날짜: 2026-10-17
- 소유자: Backend
- 관련 이슈: #751, #697

## 맥락

집계 코어를 실제 상세 진입 POST에 연결한다. 호버/prefetch GET은 방문으로 집계하지 않으며 본인 방문도 제외한다. 조회수는 게시글 상세 화면의 기존 삭제 버튼을 볼 수 있는 사용자에게 공개한다. Colog의 OWNER·ADMIN도 기존 삭제 권한에 따라 숫자를 봐야 한다.

## 결정

- 정상·중복·본인 방문 POST는 본문 없는 204다. GET은 증가시키지 않는다.
- 발행·미삭제·읽기 권한을 확인한 뒤 인증 ID가 작성자면 Counter 호출을 생략한다. 다른 독자는 기존 계정 ID/익명 UUID와 1시간 정책을 사용한다. 삭제 권한과 집계 제외는 서로 다른 기준이다.
- 익명 UUID는 별도 HttpOnly 30일 쿠키로 유지하고 잘못된 값은 교체한다. 비회원의 실제 인물이나 과거 로그인을 추정하지 않는다.
- 상세 DTO의 nullable Long viewCount는 **기존 viewerPermissions.canDelete()가 true일 때만** 채운다. 기존 판정 외에 OWNER/ADMIN 분기·권한 클래스·canViewCount 필드·권한별 DTO를 추가하지 않는다.
- 기존 상세 읽기 검증을 먼저 수행하고 비공개 읽기 범위는 넓히지 않는다.
- 전체·블로그·챕터·트렌딩 피드의 조회수 필드와 읽기를 모두 제거한다. 피드 관련 변경을 원복하고 불필요한 bulk API도 제거한다.
- 상세 GET/HEAD에 조회수 전용 캐시 제어 인터셉터를 추가하지 않는다. 공통 HTTP 캐시 정책은 별도로 다룬다.
- 등록 기본값은 비활성이다. 개발에서 명시적으로 켜고 운영 집계는 DB writer와 요청 제한 준비 후 시작한다.

## 결과와 대안

초기 작성자 전용/피드 공개 설계는 사용자 정정으로 폐기했다. 동일 상세 DTO에서 삭제 권한이 있으면 숫자, 없으면 null로 반환한다. 클라이언트는 기존 삭제 버튼 조건을 표시에도 사용할 수 있다. Colog의 다른 글 작성자가 아닌 OWNER/ADMIN 방문은 집계되며 본인 글 방문만 제외한다. POST에 숫자를 넣거나 즉시 재조회하도록 강제하지 않는다.

ADR 0007의 저장 테이블·발행 초기화는 유지하고 모든 상세 독자에게 숫자를 반환하던 정책만 대체한다. Counter 락·수명과 Caffeine 선택은 ADR 0008/0009를 따른다. DB writer·배치 스케줄·종료 저장·다중 JVM·Redis·frontend는 범위 밖이다. 쿠키/호환성/개발 설정은 [조회 등록 API](../../backend/docs/post-view-registration.md)를 따른다.
