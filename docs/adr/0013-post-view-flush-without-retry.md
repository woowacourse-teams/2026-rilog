# ADR 0013: 조회수 배치 저장 실패 시 재시도하지 않고 증가분 폐기

- 상태: 대체됨 ([ADR 0014](0014-post-view-flush-retry.md))
- 날짜: 2026-10-18
- 소유자: Backend

## 맥락

조회수는 참고용 지표이며, 메모리 증가분을 DB에 저장하지 못하면 일부 유실되는 것을 허용한다. 저장 실패 재시도를 위해 배치 기록을 계속 보관하는 비용과 정리 정책을 줄인다. 이 결정은 ADR 0007의 배치 이력 저장 결정을 대체한다.

## 결정

- 기존 10분 fixed-delay 주기로 게시글별 증가분을 저장한다. DB I/O는 Counter 잠금 밖에서 수행한다.
- `pendingDelta`를 `inFlightBatch`로 분리하고, 해당 배치는 한 실행에만 반환한다. 저장 중인 배치는 다른 실행에 재전달하지 않는다.
- DB 저장 성공 후 `completeFlush`로 확정 누계에 더한다. 저장 또는 메모리 완료 처리에서 예외가 발생하면 `discardFlush`로 해당 배치만 폐기하고 로그를 남긴다. 이후 게시글의 처리는 계속한다.
- 폐기할 때 확정 누계, 저장 중 새로 들어온 증가분, 독자 중복 제한 기록은 변경하지 않는다. 다음 정기 실행은 새 증가분을 저장한다.
- UUID는 메모리에서 완료·폐기 요청이 현재 배치와 일치하는지 확인하는 용도로 유지한다. `post_view_flush_batch` 조회·INSERT와 해당 Entity·Repository는 제거한다.

## 이유와 대안

정확한 저장과 재시도를 유지하는 대안은 중복 반영 방지 기록과 보존 정책이 필요하다. 조회수 일부 오차를 허용하는 제품 정책에 맞춰 한 번 저장을 시도하고 실패분을 버리는 구조를 선택한다.

## 결과와 후속 작업

- 실패한 게시글 배치의 증가분은 복구하지 않는다. 장애가 길어지면 여러 주기의 증가분이 유실될 수 있다.
- 화면은 저장 중 증가분도 포함하므로 폐기 직후 조회수가 내려갈 수 있다.
- DB 커밋 후 통신 또는 메모리 완료 처리가 실패하면 DB는 증가했지만 메모리에서는 폐기될 수 있다. 이 경우 재로딩 전까지 누계 차이를 허용하며, 확인되지 않은 배치를 다시 UPDATE하지 않는다.
- 서버 종료 시 메모리에만 있는 증가분의 유실도 기존처럼 허용한다.
- 요청·응답과 조회수 공개 권한은 바뀌지 않는다. 프론트엔드 변경은 없다.
- 기존 V4 마이그레이션과 배치 기록 테이블·기존 데이터는 보존한다. 새 기록은 쌓이지 않으며, 테이블 삭제는 필요할 때 별도 마이그레이션으로 진행한다. 이전 writer로 롤백할 수 있도록 이번 변경에서는 스키마를 삭제하지 않는다.
- 조회수를 과금·순위 등 정확한 집계가 필요한 기능에 사용하게 되면 재시도·복구 정책을 다시 결정한다.
