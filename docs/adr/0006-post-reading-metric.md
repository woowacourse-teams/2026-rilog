# ADR 0006: 게시글 읽기 상태를 방문 단위로 수집

- 상태: 제안
- 작성일: 2026-10-03
- 관련 이슈: #690

## 배경

기존 `post read engaged`는 글의 50% 지점에 처음 도달할 때 한 번 발생한다. 그 순간의 `engagement_seconds`만 기록하므로, 5초에 50% 지점에 도달한 뒤 30초까지 머물러도 기존 기록은 5초로 남는다. 기존 이벤트에 체류시간 필터를 추가해 읽기를 집계할 수 없다.

초기 읽기 기준은 50% 도달과 누적 가시 체류 20초지만, 20초는 최적값으로 확정되지 않았다. 프론트엔드가 20초 미만 방문을 버리면 운영 데이터에서 10초·20초·30초 기준을 비교할 수 없다.

## 결정

- 프론트엔드는 읽기 여부를 판정하지 않고, 해당 글 방문의 누적 가시 체류시간과 50% 도달 이력을 `post reading progress`로 수집한다. 이벤트에는 `post_id`, 방문마다 새로 만든 비개인 식별자 `reading_visit_id`, 실제 누적 `engagement_seconds`, `has_reached_50_percent`, `read_tracking_version: 2`를 담는다.
- 문서가 보이는 동안 누적 가시시간 10초 간격으로 상태를 전송한다. 최초 50% 도달, 문서 숨김, 글 이동·실제 언마운트·`pagehide`에도 현재 상태의 전송을 시도한다. 10초는 수집 간격이며 읽기 기준이 아니다. 같은 시간·깊이 상태의 중복 전송은 생략한다.
- `visibilitychange` 없이 `pagehide`가 발생해도 그 시점에 시간을 멈춘다. 숨김 시간은 누적하지 않고 같은 방문에서 다시 보이면 이어 센다. 다른 페이지나 글로 이동한 뒤 재방문하거나 `pagehide` 이후 `pageshow`로 복귀하면 시간·깊이 이력·방문 ID를 새로 시작한다. 같은 글의 재렌더링과 StrictMode effect 재실행은 새 방문이나 이탈로 취급하지 않는다. 마우스·키보드 활동 조건은 없다.
- 기존 뷰포트와 본문 높이 기반 깊이 계산을 유지한다. 50%에 한 번 도달하면 위로 스크롤해도 true를 유지한다. 기존 `post read engaged`의 이름·속성·최초 50% 도달 의미는 바꾸지 않는다. Backend API 계약은 바꾸지 않는다.

## 검토한 대안

- 기존 `post read engaged`에 시간 필터 적용: 깊이 도달 이후의 체류시간이 없어서 방문의 최종 체류시간을 복원할 수 없다.
- `post read qualified`를 20초에 한 번 전송: 기준 미만 방문이 빠지고 나중에 기준을 낮춰 분석할 수 없다.
- 매초 이벤트 전송: 같은 방문에서 수집량과 중복 집계 위험이 크게 늘어난다. 10초 간격과 상태 변화·이탈 시 전송으로 제한한다.
- 기존 `navigation_visit_id`나 세션 ID 재사용: `navigation_visit_id`는 글 ID로 key 처리된 탐색 Provider가 필요할 때 생성하므로 일반적인 글 이동·재방문은 구분한다. 하지만 동일 Provider가 유지되는 `pagehide`·`pageshow` 복귀에서는 ID가 남는다. 읽기 시간의 초기화 경계와 일치시키기 위해 별도 ID를 사용한다. 세션 ID는 글 방문보다 범위가 넓다.

## 집계와 결과

대시보드는 `read_tracking_version = 2`인 `post reading progress`를 `reading_visit_id`별로 묶고, 방문별 `engagement_seconds` 최댓값과 `has_reached_50_percent`의 한 번이라도 true 여부를 사용한다. 기본 읽기 기준은 **50% 도달 AND 누적 가시 체류시간 20초 이상**이다. 같은 데이터로 10초·30초 기준도 비교한다. 상태 이벤트 한 건을 읽기 한 건으로 세지 않는다.

일일 독자 수는 기준을 충족한 방문의 고유 사용자 수, 읽은 글 수는 기준을 충족한 사용자·`post_id` 조합의 중복 제거 수로 정의한다. 팀·테스트 사용자 제외는 기존 운영 설정을 확인한다. 기존 50% 이벤트와 새 계측 데이터는 합산하지 않는다. 운영 배포 SHA·적용 시각·최초 수집 시각을 기록한 뒤 새 지표의 시작점을 정한다.

현재 분석 경계는 PostHog JS SDK의 `capture` 호출을 사용한다. 문서 숨김과 `pagehide`에서는 SDK에 `transport: 'sendBeacon'`을 요청하지만, 브라우저·SDK가 이를 사용하더라도 서버 수집 성공은 보장되지 않는다. 특히 10초 미만 이탈이나 브라우저 종료 때 마지막 상태가 누락될 수 있고, 전송 간격만큼 관측된 최댓값이 실제 체류보다 작을 수 있다. 되돌릴 때는 새 이벤트 전송과 이를 사용하는 대시보드 연결을 제거하며 기존 `post read engaged`는 유지한다. 배포 후 점검은 [읽기 계측 QA](../qa/post-reading-metric.md)에 따른다.
