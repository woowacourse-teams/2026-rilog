# ADR 0006: 게시글 읽기 지표의 가시 체류시간과 깊이 기준

- 상태: 제안
- 작성일: 2026-10-03
- 관련 이슈: #690

## 배경

기존 `post read engaged`는 글의 50% 지점에 처음 도달할 때 한 번 발생한다. 그 순간의 `engagement_seconds`만 기록하므로, 5초에 50% 지점에 도달한 뒤 20초 이상 읽어도 기존 기록은 5초로 남는다. 기존 이벤트에 20초 필터를 추가하면 실제 읽기를 누락한다.

## 결정

- 50% 이상 지점 도달 이력과 문서가 보이는 동안의 누적 체류 20초를 모두 충족하면 새 `post read qualified`를 글 방문당 한 번 전송한다. 조건의 순서는 무관하다. 활동 여부는 조건에 넣지 않는다.
- 숨김 시간은 누적하지 않고 같은 방문에서 다시 보이면 이어 센다. 다른 페이지나 글로 이동한 뒤 재방문하면 시간과 깊이 이력을 0부터 시작한다. 재렌더링과 StrictMode의 effect 재실행은 새 방문이 아니다.
- 기존 깊이 계산과 `post read engaged`의 최초 50% 도달 의미는 유지한다. 새 이벤트에는 `post_id`, 실제 누적 `engagement_seconds`, `scroll_depth_bucket: 50_percent`, `read_tracking_version: 2`를 기록한다.
- 기존 PostHog 사용자 식별을 사용한다. 새 방문 식별자나 개인정보는 추가하지 않는다. Backend API 계약은 바꾸지 않는다.

## 검토한 대안

- 기존 이벤트에 20초 필터 적용: 깊이 도달 이후 체류한 시간을 기록하지 않아 새 기준에 맞는 읽기를 복원할 수 없다.
- 주기적인 체류 이벤트 전송: 단일 방문의 읽기 판정에 필요하지 않고 수집량과 중복 집계 위험을 늘린다.

## 결과와 후속 작업

- 새 지표는 `read_tracking_version = 2`와 실제 운영 적용 시점을 기준으로 집계한다. 기존 50% 이벤트의 과거 데이터와 합산하지 않는다.
- 일일 독자 수는 새 이벤트의 일별 고유 사용자 수, 읽은 글 수는 사용자·`post_id` 조합의 중복 제거 수를 사용한다. 팀·테스트 사용자 필터는 기존 운영 설정을 확인해 적용한다.
- 되돌릴 때는 새 이벤트의 전송과 그 이벤트를 사용하는 대시보드 연결만 제거한다. 기존 `post read engaged`와 과거 데이터는 유지한다.
- 배포 SHA·적용 시각·최초 운영 수집 시각을 기록하고 실제 탭 전환, 재방문, 사용자 필터를 확인한다. 상세 점검은 [읽기 계측 QA](../qa/post-reading-metric.md)에 따른다.
