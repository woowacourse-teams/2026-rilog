# ADR 0015: 모바일 인라인 댓글 선택과 탐색

- 상태: 채택
- 작성일: 2026-10-26
- 관련 이슈: #782

## 배경

모바일에서는 신규 선택 툴바를 차단하고 전체 높이 사이드바를 사용했다. 댓글창은 React 상태만 바꾸므로 브라우저 뒤로가기가 상세페이지를 떠나는 경우를 앱에서 막지 못했다.

## 결정

- 모바일(768px 미만)의 플로팅 버튼은 댓글 아이콘과 `전체 댓글`로 표시하고 전체 댓글 바텀시트를 연다. 본문 상단의 전체 보기 진입점은 모바일에서 숨기며 PC의 전체 보기와 선택 진입 UI는 유지한다.
- 모바일 작성은 브라우저의 길게 누르기·선택 핸들을 사용한다. `selectionchange`로 유효한 본문 범위를 읽어 선택 끝에 기존 검정색 `＋ 댓글 추가` 버튼을 즉시 표시한다. 모바일 본문에서 pointer/touch/contextmenu 기본 동작이나 스크롤을 차단하지 않으며 네이티브 메뉴를 수정하지 않는다. `pointerup` 수신을 기다리지 않고 범위 변경·pointercancel에도 갱신한다. 버튼 활성화 중에는 직전 선택을 보존해 포커스 변화로 인용을 잃지 않는다.
- PC의 플로팅 선택 모드는 하단 안내와 취소를 제공하고 문서 스크롤 위치·스크롤바 공간을 유지하며 스크롤을 잠근다. 보이는 단일 블록을 직접 드래그하고 선택 끝의 `＋ 댓글 쓰기`로 확정한다. 선택 모드에서도 기존 ACTIVE 밑줄을 유지하고 밑줄·블록 버튼의 상호작용을 잠시 중지한다.
- UTF-16 offset, 허용 블록, 코드 블록 제외, 동일 ACTIVE 영역 재사용, 인증과 초안 보존은 기존 계약을 따른다. 서버 API는 변경하지 않는다.
- 768px 미만 댓글창은 70% 높이의 바텀시트로 열고 손잡이와 헤더, 댓글 목록에서 95%까지 확장하거나 축소·닫기 한다. 목록에서는 축소 상태의 위쪽 드래그로 확장하고 맨 위의 아래쪽 드래그로 시트를 움직인다. 확장된 목록의 위쪽 드래그와 스크롤 중인 목록의 아래쪽 드래그는 브라우저의 스크롤·관성을 유지한다. 처음 세로 이동 의도에서 동작을 정하고 같은 제스처 중에는 전환하지 않는다. 입력창·버튼·링크는 제외하고 가로 드래그와 텍스트 선택을 방해하지 않는다. 시트 이동은 CSS translate 전환을 사용하고 열기·닫기 속도를 구분한다. 아래로 당길 때는 내용 높이를 유지한 채 시트를 이동하며, 애니메이션 완료 후 모달을 닫는다. 동작 줄이기 설정을 존중한다. 키보드와 safe area를 반영한다. 모바일 시트에서는 X 버튼을 제공하지 않고 손잡이·배경 터치·뒤로가기·Escape로 닫는다. 데스크톱 닫기 버튼은 유지한다.
- 모바일에서 바로 작성하는 시트는 네이티브 포커스가 발생하기 전에 최종 화면 위치로 배치한다. 작성 진입에서는 시트 상승 전환을 생략해 화면 아래 입력에 포커스가 들어가는 경쟁을 없애며 읽기 진입·닫기·드래그 전환은 유지한다. 키보드 회귀 검사는 상승 구간을 제외하지 않고 최초 포커스 순간부터 입력바 가시성을 확인한다.
- 모바일 작성은 스크롤 목록 밖의 하단 입력바를 사용한다. 인용문은 PC와 같은 상단 인용 영역에 표시하고 하단 입력바에서는 반복하지 않는다. PC와 모바일 모두 같은 입력 컴포넌트를 사용하며 작성 버튼을 입력창 테두리 밖 오른쪽에 배치한다. 모바일 작성·수정 입력은 실제 16px 글자 크기로 표시하며 축소 변환을 사용하지 않는다. 입력은 최대 4줄까지 늘어나고 작성 버튼은 44px 높이를 유지한다. 목록 중간의 별도 작성 버튼 없이 인용문 자체를 눌러 대상을 선택하며 접기·펼치기는 화살표로 구분한다. 대상별 초안·기존 mutation 정책을 유지한다. 읽기 진입에서는 키보드를 자동으로 열지 않는다. 하단 고정 입력바에는 포커스·뷰포트·크기 변경에 따른 자동 스크롤을 적용하지 않는다. 시트의 상단은 `visualViewport.offsetTop + visualViewport.height - 시트 높이`로 지정해 레이아웃 뷰포트와 보이는 화면의 높이 차이에 영향받지 않는다. 입력에 포커스한 동안 바닥 safe-area 중복 여백을 제거하며, 입력에 포커스한 동안 높이는 전환 애니메이션 없이 키보드 변화를 따른다. 시트의 진입·닫기 이동 애니메이션은 유지한다.
- PC 선택 모드와 모든 댓글창은 상세페이지 위의 이력 한 단계로 표현한다. 선택 확정은 같은 이력을 댓글 작성 상태로 바꾼다. 첫 뒤로가기는 닫기, 다음 뒤로가기는 이전 페이지 이동이다. 직접 댓글 링크도 상세페이지로 닫을 수 있다.
- 댓글 목록은 모달·도킹 패널을 다시 열거나 사용자가 다른 인용·전체 댓글 조회를 요청할 때 맨 위로 초기화한다. 데이터 재조회·작성 완료·키보드 및 시트 크기 변경은 초기화 기준에서 제외하며 입력 초안을 유지한다.
- `본문으로 이동`은 모달의 실제 닫힘과 포커스 복원이 끝난 뒤 실행한다. 넓은 PC 화면에서는 패널을 유지한다. 인용이 이미 보이면 불필요한 스크롤을 피하고, 이동·키보드 뷰포트가 안정된 뒤 정확한 인용 범위를 1초간 강조하고 0.5초에 걸쳐 지운다. 기존 밑줄과 네이티브 Selection은 유지하며 반복 이동·새 댓글 진입·언마운트 시 이전 강조를 정리한다. 동작 줄이기 설정에서는 즉시 이동과 1초 정적 강조를 사용한다.
- 댓글 모달은 native dialog.open을 실제 열림의 단일 기준으로 삼는다. 정리 시에는 마운트 때 캡처한 DOM 노드를 닫아 Strict Mode 재마운트·ref 해제 후에도 모달 잠금이 남지 않게 한다. 초기 포커스 참조 변경은 열린 모달을 다시 열지 않으며, 닫는 도중 재진입하면 닫기를 취소하고 열린 상태를 복구한다.
- 댓글 패널을 닫거나 다른 조회를 열면 하위 삭제 확인·오류 모달도 종료한다. 이전 열림에서 시작한 요청이 나중에 실패해도 숨은 모달이나 재진입한 화면의 오래된 오류를 열지 않으며, 수정 초안은 유지한다. 늦은 수정 성공은 닫힌 패널이나 새 조회로 포커스를 이동시키지 않는다.
- 댓글 모달은 native dialog의 브라우저 뒤로가기 처리와 앱의 이력 처리가 중복되지 않게 한다. Escape·닫기·배경 터치는 기존 접근성 경로로 처리한다.
- 분석 이벤트의 `entry_source`에 `floating_button`을 추가해 기존 `selection_toolbar`와 구별한다. 본문·선택 텍스트는 분석 이벤트로 보내지 않는다.

## 결과와 검증 경계

- PC 직접 드래그 모드는 화면 밖 문장을 선택할 수 없는 제약을 의도적으로 수용한다. 여러 블록 선택이나 자동 스크롤은 범위 밖이다.
- 브라우저 History·Selection·터치와 시트 제스처는 Playwright로 검증한다. 실제 iOS Safari와 Android Chrome의 소프트 키보드·OS 선택 동작은 데스크톱 엔진 자동화로 완전히 증명할 수 없으므로 별도 기기 검증 여부를 보고한다.
