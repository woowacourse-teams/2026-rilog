# ADR-0004: 온보딩 토큰 기본 만료시간을 24시간으로 연장

- 상태: 적용
- 날짜: 2026-09-28
- 관련 이슈: #656
- 영향: backend 인증 설정. frontend API 계약 변경 없음.

## 맥락

온보딩 양식을 오래 열어 둔 사용자가 기존 10분 만료시간 때문에 제출에 실패할 수 있다. 온보딩 토큰은 GitHub 인증 후 `PENDING` 사용자에게 발급되며, 온보딩 완료와 업로드용 presigned URL 발급에 사용할 수 있다.

## 결정

온보딩 토큰의 기본 만료시간을 발급 시점부터 24시간으로 늘린다. `ONBOARDING_TOKEN_EXPIRATION` 환경변수로 다른 값을 지정한 배포는 그 값을 계속 우선한다. 액세스 토큰과 리프레시 토큰의 만료시간 및 권한은 변경하지 않는다.

## 이유

사용자가 같은 브라우저 탭에서 온보딩 양식을 장시간 작성할 수 있게 한다. 토큰에 허용된 작업은 온보딩 완료와 presigned URL 발급으로 제한되어 있다.

## 검토한 대안

- 10분 유지: 양식 작성 중 만료 문제가 계속된다.
- 만료 시 토큰 갱신: 별도 갱신 수단과 프론트엔드 흐름이 필요하다. 이번 변경의 범위를 넘는다.

## 결과와 후속 작업

- 얻는 이점: 같은 탭에서 장시간 작성한 온보딩 양식을 제출할 수 있다.
- 감수하는 비용/위험: 토큰 탈취 시 최대 24시간 동안 허용된 작업에 사용할 수 있다. 온보딩 완료는 이미 완료된 사용자에게 거부되지만, 기존 온보딩 토큰으로 presigned URL을 발급받는 것은 만료 전까지 가능하다. 토큰은 클라이언트 메모리에만 있으므로 새로고침하거나 탭을 닫은 뒤 가입을 이어서 진행하는 문제는 해결되지 않는다.
- migration/rollback: 새로 발급한 토큰에만 새 만료시간이 적용된다. 배포 환경에서 `ONBOARDING_TOKEN_EXPIRATION`을 지정했다면 운영값을 `24h`로 갱신해야 한다. 되돌릴 때 기본값과 배포 환경값을 함께 조정한다. 이미 발급한 토큰의 `exp`는 변경되지 않는다.
- 다시 검토할 조건: 온보딩 재접속 지원, 토큰 폐기 또는 업로드 권한 축소가 필요해지거나 온보딩 토큰 오용이 관찰될 때.
