# ADR 0005: 프론트엔드 외부 값의 런타임 검증 경계

- 상태: 적용 중
- 날짜: 2026-09-27
- 관련 이슈: #629
- 영향: frontend. Backend 요청·응답 계약 변경 없음.

## 배경

`strict`와 타입 기반 ESLint는 소스 안의 타입 불일치를 찾지만, HTTP JSON과 브라우저 저장소의 실제 값은 확인하지 못한다. 현재 일부 API는 `.json<T>()`의 `T`를 그대로 소비해 잘못된 인증 상태, 빈 본문 fallback 또는 손상된 쓰기 후처리로 이어질 수 있다. 모든 응답을 한 번에 스키마화하면 변경량과 유지 비용이 커진다.

## 결정

인증·게시글/초안 상세·쓰기 응답·업로드 presign·필드 오류·로그인 redirect를 우선 검증한다. 최신 develop에서 추가된 인라인 댓글 조회·쓰기 응답도 선택 경계에 포함한다. URL 및 분석 저장소는 기존 가드를 보완한다. 선택한 endpoint는 소비하는 한두 필드만이 아니라 반환 DTO의 필수 구조를 검사하고, 기존 optional/null 계약을 유지하며 추가 필드는 허용한다. 미검증 조회·쓰기 응답과 환경변수는 현재 코드의 방어·남은 위험·검증 전환 조건을 [TypeScript 기준](../harness/frontend-typescript.md)에 기록한다.

검증은 `unknown`에서 시작해 기존 resource의 raw API 함수가 JSON 파싱 직후 수행한다. 본문 decoder는 `domains/post`의 순수 모듈로 두고 실제 편집기의 활성 BlockNote 스키마를 따른다. 알 수 없는 블록과 손상된 중첩 구조는 오류이며 정상 빈 배열 `[]`은 허용한다. 검증된 `content`는 `Block[]`로 전달해 mapper의 배열 확인 뒤 단언과 빈 본문 fallback을 제거한다. 가드는 React·DOM·편집기·서버 렌더러를 런타임 import하지 않는다.

성공 응답의 JSON 문법 오류와 데이터 구조 오류를 같은 응답 확인 실패로 처리한다. 검증 실패는 별도 Error 하위 타입으로 표현해 기존 `unknown` 오류 정규화·Sentry privacy 경계·오류 UI를 사용한다. 응답 원문, 파싱 오류 원문, 토큰, 본문, 서명 URL은 오류에 넣지 않는다. 검증 실패를 네트워크 실패로 취급하거나 자동 재시도하지 않는다. 쓰기 응답이 손상됐더라도 서버 저장이 이미 완료됐을 수 있으므로 성공 후처리를 멈추고 작성 내용을 보존하며 자동 재전송하지 않는다. 이 경우 관련 목록 cache를 무효화해 확인에 사용할 최신 결과를 다시 가져온다.

## 검토한 대안

- 전체 API 응답을 일괄 스키마화: 위험과 무관한 변경량이 크고 DTO·가드 이중 관리 비용이 즉시 늘어난다.
- `.json<T>()`와 타입 단언만 사용: 실제 응답을 검사하지 못한다.
- 범용 schema 엔진 추가: 현재 선택한 경계에서는 기존 타입 가드 확장으로 충분하며 새 의존성이 필요하지 않다.
- 손상된 본문을 빈 배열로 대체: 저장 시 기존 글을 덮어쓸 수 있어 허용하지 않는다.

## 결과와 검증

정상 계약과 malformed 응답을 raw API 경계에서 검증하고, 인증 미확정·업로드 PUT 미실행·본문 덮어쓰기 방지·쓰기 성공 후처리 중단을 확인한다. BlockNote 스키마 변경 시 기존 저장 문서 fixture와 decoder를 함께 갱신한다. 선택하지 않은 endpoint는 인증·편집·쓰기 후처리에서 사용되거나 계약 장애가 나타나면 승격한다. JWT 진위와 권한 판정은 계속 서버 책임이다.
