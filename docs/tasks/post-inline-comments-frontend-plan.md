# 게시글 인라인 댓글 프론트엔드 작업 계획

상위 이슈: #570 — 게시글 인라인 댓글 기능 구현

## 목표

기존 서버 렌더링 본문을 유지하면서 텍스트에 연결된 댓글의 조회·작성·수정·삭제와 본문 탐색을 제공한다. 완료된 #570 작업 브랜치를 리뷰 가능한 PR로 나누어 develop에 순서대로 통합한다.

각 PR은 해당 하위 이슈만 닫는다. #570은 전체 하위 PR 병합 및 통합 검증 후 닫는다.

## #639의 통합 경계

- 선택·Range 복원·하이라이트와 callback 계약을 먼저 제공한다. 실제 조회·mutation 및 사이드바는 후속 PR에서 연결한다.
- `features/post-detail/model/inline-comment.ts`는 화면 모델이다. API 응답 DTO로 취급하지 않는다.
- `PostDetailContent.inlineCommentBlocks`로 테스트 데이터를 주입할 수 있다. 실제 상세 화면에는 fixture나 댓글 API를 연결하지 않아 동작하지 않는 댓글 진입점이 노출되지 않는다.
- 선택 범위는 한 지원 텍스트 루트의 UTF-16 offset이며 시작 포함·끝 제외다. 여러 블록 횡단, 코드 블록, 공백 선택을 차단한다. 문단 내부 인라인 코드는 지원한다.
- ACTIVE만 본문에 표시하고, 복원 실패한 범위만 생략한다. 서버 상태 재판정·텍스트 재검색·offset 보정을 하지 않는다.
- 서버 배열의 뒤쪽 앵커가 중첩 위치의 우선 대상이다. 키보드 진입점과 블록 버튼은 상위 controller에 대상 정보를 전달한다.
- blocknote-content.css는 상세 본문과 글쓰기 편집기가 공유하므로 양쪽의 브라우저 회귀를 검증한다.

## #640의 조회 계약과 후속 연결

#640은 실제 API DTO의 selectionId, commentAnchorId, ORPHANED, anchorCount, isEdited 및 본문·사이드바 별도 응답을 화면 모델에 매핑한다. 인증 초기화 후에만 조회하며 로그인 여부별 캐시를 분리한다. 게시글 수정 시 해당 글의 본문·사이드바 및 로그인·비회원 캐시를 함께 무효화한다. 실제 페이지의 조회·사이드바 조립은 #641에서 연결한다. 화면에서는 OUTDATED로 표현한다. #641의 모바일 UI는 전체 너비 사이드바이며 초기 BottomSheet 계획을 대체한다. #642·#643은 UI와 해당 mutation을 같은 PR에서 검증한다.

## 검증과 완료 조건

- 각 기능의 단위·컴포넌트 테스트를 해당 PR에 포함한다.
- Node 24.19.0, pnpm 11.21.0에서 pnpm check를 실행한다.
- 브라우저의 Selection·Range 좌표와 반응형 상호작용은 해당 Playwright 검증으로 확인한다.
- 공유 스타일 변경에 대해 기존 글쓰기 필수 4개 브라우저 흐름을 유지한다.
- 필수 검사를 삭제하거나 약화하지 않는다. 과거 삭제된 blocknote-content.spec.ts를 복원하지 않고 현재 테스트 구조에 필요한 검증만 추가한다.
- 실제 API와 결합된 최종 CRUD·오류·권한·모바일 흐름은 각 후속 PR과 #570 통합 완료 시 검증한다.

## #641의 사이드바 통합 경계

- 실제 상세 페이지에서 #640의 본문·사이드바 조회 hook을 연결한다. 로딩·실패·재시도·빈 목록을 표시한다.
- 전체 댓글은 서버의 사이드바 배열 순서대로 표시한다. 블록 진입점은 해당 블록의 ACTIVE 인용만, 하이라이트 진입점은 해당 인용만 표시한다.
- 단일 인용은 항상 펼치고 전체·블록 목록은 접기·펼치기를 제공한다. OUTDATED는 전체 목록에서 읽을 수 있으며 본문 이동을 제공하지 않는다.
- 작성자 아바타·배지·프로필 링크와 수정 여부를 표시한다. 모바일 사이드바는 전체 너비를 사용한다.
- 이번 PR은 읽기·탐색만 제공한다. 댓글 작성 입력은 #642, 수정·삭제 control은 #643에서 연결한다.
- 기존 블록 배열 재조립 helper는 평면 사이드바 조회 응답으로 대체한다. 실제 query hook과 raw API mock을 연결한 workspace 통합 테스트에서 순서·필터·오류를 검증한다.

## #642의 작성 통합 경계

- 데스크톱의 지원 본문을 선택하면 댓글 추가 툴바를 표시한다. 동일한 ACTIVE 선택 영역은 기존 selectionId로 작성하고 나머지는 신규 선택 영역 API로 작성한다.
- 세션 초안은 신규 선택의 게시글·블록·범위·인용문 또는 기존 selectionId를 기준으로 저장한다. 닫기·재진입·실패 시 보존하고 성공 시 제거한다.
- 인증 초기화 전·비회원·빈 입력·요청 중에는 작성을 막는다. 본문 변경 409는 다시 선택하도록 안내한다.
- 두 mutation은 해당 게시글의 본문·사이드바와 로그인 여부별 캐시를 무효화한다. 서버 응답의 commentAnchorId로 새 댓글의 스레드를 찾아 연다.
- RTL은 실제 query/mutation과 raw API mock으로 작성·조회 갱신·실패·초안·중복 제출을 검증한다. 기존 #641 탐색 검증도 유지한다.
- Playwright는 실제 workspace·툴바·사이드바·API 코드를 테스트 번들로 실행한다. 서버 본문·분석 경계만 고정 본문으로 대체하고 요청을 route로 제어하여 운영 게시글에 의존하지 않는다. Vitest가 사용하는 잠금 버전 Vite를 재사용하며 앱 route나 새 의존성을 추가하지 않는다.
- 브라우저 Selection 좌표, 스크롤에 따른 툴바 이동, 입력 focus, 모달 닫기·초안 복원, 신규·추가 작성, 모바일 툴바 차단은 jsdom으로 확인할 수 없어 별도 E2E로 보호한다. 기존 글쓰기 4개 필수 흐름은 유지한다.

## #643의 수정·삭제 통합 경계

- 서버의 canEdit·canDelete에 따라 동작을 제공한다. 수정 취소 시 원문, 실패 시 편집 내용을 보존하며 저장 성공·취소 후 수정 버튼에 focus를 복원한다.
- 삭제는 확인 모달에서 실행하며 요청 중 중복 제출과 모달 닫기를 차단한다. 실패 시 댓글을 유지하고 오류 모달 후 재시도할 수 있다.
- 수정 PATCH와 JSON 응답을 반환하는 DELETE를 현재 백엔드 DTO에 맞춰 연결한다. 두 mutation은 성공 후 해당 게시글의 본문·사이드바 및 로그인 여부별 조회를 무효화한다.
- 공통 ConfirmModal의 기존 isPending 동작을 재사용한다. 원본 커밋의 사용되지 않는 isConfirmDisabled 확장은 포함하지 않으며 공통 모달과 기존 소비자 검증을 유지한다.
- RTL은 권한 조합, 편집·취소·실패·재시도, pending과 focus를 실제 mutation/raw API 경계로 검증한다. 기존 독립 브라우저 작성 시나리오를 확장하여 수정 결과·편집됨·focus 및 중첩 삭제 모달의 pending Escape 차단과 성공 후 목록 갱신을 확인한다.

## #644의 댓글 수 표시

- 전체 피드와 블로그 게시글 목록의 totalCommentsCount를 도메인 모델로 매핑하고 공통 PostCommentCount로 표시한다. 숫자 0도 표시하고 스크린리더에는 댓글 개수를 제공한다.
- 기존 상세·프로필 링크, 키보드 탐색, 진입 context와 목록 상태를 유지한다. 이미 통합된 댓글 아이콘과 하이라이트는 변경하지 않는다.
- 2026-09-27 확인: 개발 서버 Swagger의 블로그 응답도 totalCommentsCount가 포함된 PostItemResponse를 참조하지만, 실제 GET /v1/blogs/gustn99/posts?page=0&size=3 응답에는 해당 필드가 없었다. GET /v1/feeds/posts?page=0&size=3에는 필드가 있었다.
- develop의 BlogFeedPostResponse와 블로그 조회 쿼리에도 댓글 수 제공이 아직 없다. 프론트는 필드 제공 시 그대로 표시하며 누락 시 기존 원본 구현대로 0을 사용한다. 이번 작업은 프론트 연결만 포함하고 서버 응답 차이를 PR과 #644에 기록한다. 블로그 실제 댓글 수 표시 인수 조건은 서버 응답 보완 후 확인하며 이 PR에서 #644를 자동으로 닫지 않는다.

## 원본 #570 최종 상태와 비교

- 비교 기준: 원본 `40a75aa07655367f21f412a28b098fed75bbf7c0`과 #650 브랜치. 원본 작업 브랜치와 작업 파일은 유지한다.
- 백엔드 차이 26개 파일은 분리 시작 전 develop에 통합된 #632·#634·#636·#638의 변경이다. 현재 백엔드는 분리 기준 `84d67c3a`와 동일하며 프론트 분리 PR에서 변경하지 않았다.
- 프론트 제품 코드 차이는 API·타입 선언 위치 정리, 동일한 ACTIVE 선택을 찾는 helper의 workspace 인라인화, 사용하지 않는 ConfirmModal 옵션 제외, 접힌 입력 영역의 aria-hidden 적용이다. 피드·블로그 댓글 수와 주요 조회·작성·수정·삭제·선택·모바일 구현은 원본과 동일하다.
- 작성 통합 테스트는 별도 파일로 분리하고 조회·캐시 검증을 확장했다. 브라우저 테스트는 실제 운영 게시글 의존을 제거한 fixture에서 실행하며 작성·수정·삭제 및 모바일 레이아웃을 검증한다. 따라서 실제 서버와 결합한 최종 전체 흐름은 별도 확인이 필요하다.
- 비교에서 빠진 원본 검증을 확인해 작성자 slug 두 형식과 프로필 키보드 접근, 스레드 내 작성자·수정·삭제 focus 순서, 인용 하나인 전체·블록 목록의 접기·펼치기 테스트를 복원했다. 집중 테스트 29개가 통과했다.
- 블로그 댓글 수 응답 누락은 원본에도 같은 fallback이 있는 기존 연동 공백이며 cherry-pick 누락이 아니다. #644의 남은 서버 조건으로 추적한다.
